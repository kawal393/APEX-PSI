   The Compliance-Receipt HTTP Header for Verifiable AI Responses
                     draft-singh-psi-http-01

Abstract

   This document defines two HTTP response header fields,
   "Compliance-Receipt" and "Compliance-Receipt-Policy", that allow an
   origin serving an AI-generated response to attach a signed,
   publicly verifiable receipt asserting that the response satisfies
   one or more regulatory predicates.  Receipts are signed using
   Ed25519 [RFC8032] over a canonical leaf and link to a public
   verification URL that any party, including regulators, can audit
   without prior coordination.

1.  Introduction

   AI systems increasingly produce decisions in regulated contexts
   (EU AI Act 2024/1689, US Executive Order 14110, NIST AI RMF, and
   others) where verifiable proof of compliance is required.  Existing
   approaches rely on out-of-band attestations.  This document defines
   an in-band mechanism: a single HTTP response header that carries a
   compact, signed receipt linking to a public audit URL.

3.  The Compliance-Receipt Header

   Compliance-Receipt   = "v=" version 1*( ";" SP param )
   version              = 1*DIGIT
   param                = rid-param / pred-param / status-param
                        / sig-param / anchor-param / verify-param
   rid-param            = "rid=" 1*VCHAR
   pred-param           = "pred=" predicate *( "," predicate )
   predicate            = registry "/" predicate-id
   status-param         = "status=" ( "compliant" / "challenged"
                                    / "violation" )
   sig-param            = "sig=" scheme ":" base64
   scheme               = "ed25519"
   anchor-param         = "anchor=" anchor-scheme ":" base64
   anchor-scheme        = "ots" / "btc" / "polygon"
   verify-param         = "verify=" absolute-URI

   The "verify" parameter is REQUIRED.  The "sig" parameter is
   REQUIRED for status=compliant.  The signature is computed over the
   value of "rid" using the issuer's Ed25519 private key.

4.  The Compliance-Receipt-Policy Header

   Compliance-Receipt-Policy = "v=" version 1*( ";" SP policy-param )
   policy-param              = mode-param / window-param / issuer-param
   mode-param                = "mode=" ( "blocking" / "optimistic" )
   window-param              = "challenge-window=" 1*DIGIT
   issuer-param              = "issuer=" 1*VCHAR

5.  Status Code Mapping

   200 OK              response carries a compliant receipt.
   200 OK              with status=challenged: predicate flagged.
   451 Unavailable     for status=violation: response blocked.

6.  Verification

   A verifier MUST:

   1.  Parse the Compliance-Receipt header.
   2.  Fetch /.well-known/compliance-receipt from the origin of the
       "verify" URL.
   3.  Resolve the issuer Ed25519 public key from the descriptor.
   4.  Verify the signature over "rid".
   5.  Optionally fetch the "verify" URL to retrieve the full receipt.

7.  Security Considerations

   The "rid" value MUST be unguessable and collision-resistant.
   Issuers SHOULD anchor receipts to a public timestamping service
   (OpenTimestamps, Bitcoin, or a public ledger such as Polygon) and
   reflect that anchor in the "anchor" parameter.
