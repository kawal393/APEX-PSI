## What the door is allowed to do

Five tools, the same names and arguments as `npx apex-psi-mcp`: `seal`, `verify`, `anchor`, `cite`,
`verify_chain`. Four are read-only. `seal` writes to the append-only ledger, anonymously, and the
free allowance — 20 operations a minute, 100 a day — is enforced by the ledger itself, which
answers 429 with its own terms rather than an error page. No account, no key, no install.

## Acceptance — eyeball this, in this order

Run these three calls and compare the answers. All three are read-only except the middle one,
which is refused before it touches anything.

```bash
URL=https://qhtntebpcribjiwrdtdd.supabase.co/functions/v1/apex-psi-mcp

# 1. handshake
curl -s -X POST $URL -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"acceptance","version":"0"}}}'

# 2. the tool table
curl -s -X POST $URL -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

# 3. a method a stateless server must refuse
curl -s -o /dev/null -w '%{http_code}\n' $URL
```

Pass looks like:

- [ ] call 1 → HTTP 200, `result.serverInfo.name` is `apex-psi-mcp`, `protocolVersion` echoed back
- [ ] call 2 → HTTP 200, exactly five tools: `seal`, `verify`, `anchor`, `cite`, `verify_chain`
- [ ] call 3 → HTTP 405 with JSON-RPC error `-32601` (GET is not offered; that is the spec, not a fault)
- [ ] `OPTIONS $URL` → 204 with `Access-Control-Allow-Origin: *`
- [ ] `POST .../functions/v1/mcp` still answers 401 `{"error":"unauthorized"}` — untouched

If any box fails, say which one and stop. Do not "fix" the door by changing its files; the
