# APEX Four-View Visual Sample Plan

## Goal
Create the visual samples first, without changing the website. The samples will show exactly how the simplified four-view APEX experience could look before implementation begins.

## Chosen direction
- **Style:** Precision Laboratory
- **Mood:** rigorous, inspectable, modern evidence infrastructure—not a generic software dashboard
- **Palette:** cool white laboratory surfaces, near-black structure, restrained APEX gold, and steel blue for technical states
- **Typography:** Space Mono for proof data and headings; Rubik for readable supporting copy
- **Layout:** structured workspace with strong hierarchy, thin rules, live-state indicators, and generous breathing room

## Sample set
Produce **eight polished concept images**:

1. **What is APEX? — desktop and mobile**
   - Immediate plain-language definition
   - APEX as the universal verification layer
   - Simple visual flow: input → fingerprint → signed receipt → independent verification
   - Clear paths to verify or create a receipt

2. **Why the world needs APEX — desktop and mobile**
   - The problem: digital actions and media change faster than evidence systems can track them
   - Evidence gaps across AI, media, enterprise records, and machine actions
   - A restrained before/after evidence comparison, without unsupported claims

3. **Explore the full APEX system — desktop and mobile**
   - A scannable directory for the existing protocol, tools, standards, ledger, developers, evidence, organisation, and legal pages
   - Preserve the depth of the current website without exposing every destination at once
   - Search and category navigation as the dominant interaction

4. **Live sealing laboratory — desktop and mobile**
   - A long-form video loaded into the workspace
   - Visible local hashing progress and video timeline
   - A persistent APEX seal track running beneath the full duration
   - Current-frame preview with the seal at the bottom
   - Receipt, fingerprint, timestamp, and verification state
   - Honest wording: the file stays local while its fingerprint is sealed; identity and authenticity are not inferred

## Shared shell
Every sample will use the same persistent four-view switcher:

```text
WHAT IS APEX | WHY APEX | EXPLORE | LIVE LAB
```

The shell will keep APEX PSI prominent, expose verification and pricing without clutter, and visibly indicate the active view. Mobile samples will use an ergonomic compact switcher rather than squeezing desktop navigation into the screen.

## Delivery and review
- Deliver the eight samples as viewable image files before any website implementation.
- Present them as one coherent family so the full journey can be judged together.
- Revise the chosen concept based on visual feedback.
- Only after approval, translate the approved samples into the working website while preserving the existing deep pages and live functions.

## Boundaries
- No website source changes during the sample stage.
- No invented live figures, customer claims, endorsements, or proof states.
- No change to the sealing engine or existing routes until the visual direction is approved.
