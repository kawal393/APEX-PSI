# Project architecture decisions

- Redirect legacy `/index` and `/index.html` app launches to `/` while preserving query parameters and hash; old phone shortcuts must retain referrals and the selected home view.
- Resolve the managed public Cloud client settings through Vite's environment loader and only warn when absent; a hard build failure blocked platform preview/publish builds whose settings are injected differently. Never edit the generated client.

- Serve C2PA WebAssembly from public/wasm and initialize the reader through a browser-only dynamic import on demand; this keeps binary imports out of server bundles.
- Exclude platform-managed preview auth storage from app lint rather than editing regenerated code; this keeps CI stable across connector syncs.
- Default the public checker to local seal verification and label online ledger matches and detected watermarks as present, not authenticated; external lookups and detection alone do not prove authenticity.
- Use C2PA validationResults success and failure arrays for credential verdicts; the reader's validationStatus is not a list of boolean success flags.
- Fetched trust-anchor documents may only select built-in pinned Ed25519 identities; new identities require an explicit pin update or a visitor-supplied key, which is labelled separately to prevent silent trust substitution.
- The public parity display imports the same signed fixtures and recorded Python output used by cross-language tests, including their explicit trust options; this prevents hand-written demonstrations from drifting from real verifier behavior.

- Keep the PSI commons separate from APEX-operated capacity: offline verification and self-hosting remain free, while the hosted allowance is capped at 20 receipts per minute and 100 per day and higher-volume products are arranged directly. This prevents public licensing promises from being confused with hosted-service capacity.
- Reserve public notary capacity atomically in a private database counter shared by single and batch endpoints. This prevents instance restarts or parallel requests from bypassing published limits.- The public witness observer records only fingerprints of open, non-personal public feeds into its own table, separate from customer receipts, with a single-flight lock and dedup key. This keeps automated observations from being confused with sealed customer evidence.
- The SCITT bridge is a JSON view returned on request alongside native PSI receipts, never a claimed COSE/SCITT conformance. This keeps interoperability honest while PSI stays the default format.
- Agent runs and media sealing reuse the notarize service (agent chain head and file digest are sealed as ordinary receipts) and the C2PA output is an informative JSON view, never a signed manifest. This keeps one quota, one ledger and honest interop claims.
- Agent runs require sign-in and run server-side only, so AI cost cannot be triggered anonymously.
- Organize the root experience as four switchable views while keeping deep routes independent and the APEX company logo visible in global navigation. This makes the large public system understandable without removing any existing surface.
- Founding Member referral fees are computed only from paid Stripe invoices on subscriptions carrying the member's ref code, recorded idempotently per invoice and settled manually each month. This keeps payouts tied to real customer revenue, never recruitment.
- Post-quantum LMS one-time slots come only from the atomic `next_lms_slot` database counter shared by every signer, and signing fails loudly instead of falling back. This prevents concurrent requests from reusing a one-time key or issuing pseudo-signatures.
- New ledger Merkle roots use the RFC 6962 profile (chronological leaf order, 0x00/0x01 prefixes) and receipts declare `merkle_profile`. This keeps roots consistent and verifiable by standard transparency-log tooling.
- Every new receipt carries a stateless ML-DSA-65 signature under the published trust-anchor key and sealing fails if it cannot be produced; inclusion proofs come from the public `merkle-proof` function over the same window the root was built from. This lets anyone verify post-quantum signatures and audit paths offline without trusting APEX.
- The Founding Member approved script, may/may-not-say lists and banned claims live in one read-only `partner_script` row, enforced server-side on applications and sent in the welcome kit. This keeps every partner on one wording no partner can edit.
- Founding seat auto-approval is off unless the backend flag `FOUNDING_AUTO_APPROVE=true`; reservation always goes through one `reserveSeat` path that emails the welcome kit. This keeps the operator gate default while making onboarding hands-free when enabled.
- Google Ads measurement loads only through `src/lib/ads-consent.ts`: the tag and conversions are blocked in consent regions (and when region is unknown) until the visitor accepts the regional banner, and every conversion call re-checks consent. This keeps ad measurement compliant with Google's EU User Consent Policy without a site-wide banner.
- Ledger proof bundles and receipt lookups are verified in the browser by `src/lib/proof-bundle-verify.ts`, fail-closed: signature required, pinned ledger key only, checked over the locally recomputed leaf; in-band media reaches VALID only under the pinned anchor (otherwise INTEGRITY_ONLY). A found row or a self-supplied key is never proof of authenticity.
- Hosted notary paths store only a fingerprint of submitted text in the ledger (sole exception: Impact Wall testimony submitted for public display), and client libraries hash at source; verification relies only on stored hashes and signatures, so the readable text is never needed server-side.
- Hosted seal replies carry an `allowance` meter (used, remaining, reset, upgrade plans) beside the receipt, never inside the signed payload, built by `_shared/allowance.ts`; downloaded receipts strip it. This turns free usage into a visible upgrade path without altering evidence.
- The public site has no AI chatbot or proactive auto-open assistant; enquiries use the contact route. This prevents visitor page views from triggering paid AI inference.
- Hosted receipts carry share links (`receipt_page_url`, `verify_command`, `proof_command`) built by `_shared/receipt-links.ts` as unsigned pointers beside the signed Merkle leaf, and the notary accepts a notary key as `x-apex-api-key` or `Authorization: Bearer apex_ntry_…`; this lets forwarded receipts explain their own verification and keeps keyed MCP ≤1.1.2 callers on their paid tier.
- Edge functions that act with the service key first resolve the caller through `_shared/caller.ts` (service key, verified sign-in, admin from `user_roles`) and fetch user-supplied URLs only through `_shared/safe-fetch.ts`; engine commits are challenged or proved only by their owner or the one-time control token. This stops anonymous callers from driving privileged writes, emails, paid AI or internal network requests.
- Compliance score and status are computed only server-side (questionnaire trigger, run-verification), and the public status lookup labels them self-reported, never verified. Browsers cannot write them, so a self-assessment is never presented as independent verification.
